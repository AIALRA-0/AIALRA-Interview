## 3. 数据与证据方法

### 3.1 来源优先级

1. 实体官方网站和官方招聘页。
2. 高校、研究所、实验室和政府平台官网。
3. 权威行业协会的实体目录或机构介绍。
4. 政府部门对尚无稳定独立官网的平台介绍。

本轮没有把商业数据库、搜索摘要、自媒体“国产替代名单”、招聘搬运站或百科作为最终证据。核心交叉核验入口包括：

- [中国半导体行业协会官网](https://web.csia.net.cn/)
- [中国半导体行业协会会员名录](https://web.csia.net.cn/hyml)
- [中国半导体行业协会集成电路设计分会](https://web.csia.net.cn/newsinfo/4555241.html)
- [中国半导体行业协会封测分会](https://web.csia.net.cn/fcfh)
- [中国科学院微电子研究所](https://www.ime.cas.cn/)
- [清华大学集成电路学院](https://www.sic.tsinghua.edu.cn/)
- [北京大学集成电路学院](https://ic.pku.edu.cn/)
- [国家智能传感器创新中心](https://www.nisic.xin/)
- [上海集成电路研发中心](https://www.icrd.com.cn/introduction.aspx?id=1)
- [广东省集成电路行业协会对大湾区研究院的介绍](https://www.gdica.net.cn/gxjyjjg)

每个 JSON 节点至少含一个证据对象：

```json
{
  "title": "来源标题",
  "url": "https://...",
  "type": "official-home | official-careers | official-institute | ...",
  "observedAt": "2026-07-23"
}
```

`lastVerified` 表示本轮观察日期，不保证页面内容在未来仍有效。稳定的公司首页不等于稳定的招聘入口；后续申请系统应保存具体 JD 的快照、发布时间、失效时间和原始链接。

### 3.2 事实、推断和未知

- `name`、机构属性、技术方向和官网属于来源支持的种子事实。
- `fitTier`、`difficulty`、`whyRelevant` 和 `gaps` 是用于排序的结构化推断，不是录取概率。
- `opportunityTypes` 表示该类实体可能采用的路径，文字统一写成“以官网/公告为准”，不表示 2026-07-23 正在开放。
- `requirements` 是筛选 JD 时应核对的能力维度，不是从单个招聘岗位复制的硬门槛。
- 无法稳定找到独立招聘入口的实体，`careerUrl` 使用官方主页、上级机构或权威平台页，置信度相应降低。

### 3.3 `visaSignal` 在中国数据中的解释

字段为与美国文件兼容而保留，但不能把它机械理解为“签证赞助”：

- `friendly`：公开跨地域/开源协作较强，仍需看具体劳动资格。
- `mixed`：普通商业岗位为主，但身份、地点、出口管制、数据或客户项目限制需逐岗核验。
- `restricted`：央国企研究所、敏感计算/通信/设备或特定项目存在更高概率的国籍、身份、保密、政审、专业目录或出口管制限制；不代表该实体的所有岗位都受限。
- `unverified`：高校、平台、协会或项目不能在实体层面下结论。

正确流程永远是：

```text
具体岗位或招生通知
→ 用工/培养主体
→ 国籍、身份、保密、专业目录、毕业时间与地点
→ 能否申请
```

## 4. 机会类型与边界

| 路径 | 如何验证 | 不能做的推断 |
|---|---|---|
| 校园招聘 | 当届官方招聘站、毕业时间窗口、岗位 JD | 公司去年校招过，所以今年一定有 |
| 实习 | 官方实习 JD、时长、到岗频率、转正规则 | 官网有“加入我们”，所以一定接受实习 |
| 社会招聘 | 当前官方 JD、经验年限、地点、职级 | 公司长期存在，所以岗位仍开放 |
| 科研助理/博士后 | 研究所、学院、导师或人事处公告 | 学院有研究方向，所以导师一定有名额 |
| 硕博/夏令营 | 当年招生简章、专业目录、夏令营通知 | 历史通知仍适用 |
| 联合培养 | 双方正式通知、导师与培养协议 | 企业和学校合作，所以个人可直接加入 |
| 开源贡献 | 官方仓库、贡献指南、issue 与评审记录 | 贡献代码等于获得雇佣或推荐 |
| 无薪/志愿 | 书面性质、劳动法合规、保险、知识产权和成果归属 | “不要钱”会自然提高录取率 |

v2 **没有宣称任何公司提供无薪实习**。对求职信号而言，优先级应是：

1. 有公开成果的开源贡献；
2. 学校或研究机构正式管理的科研/联合培养；
3. 有合同、导师、成果和合规边界的短期项目；
4. 最后才考虑所谓“无薪实习”，且必须先核验法律、保险、知识产权、推荐信和实际指导。

没有正式管理、要求接触商业代码或数据、只承诺“以后给证明”的无薪机会应视为高风险。

## 5. 难度、优先级和置信度

### 5.1 难度

- `S`（88）：顶级技术平台、热门 GPU/AI/CPU/机器人岗位、头部高校/研究所，或资格约束强。
- `A`（160）：技术门槛明确、需要方向匹配和可验证项目。
- `B`（25）：相对更适合作为早期入口，但仍不代表容易录取。
- 本轮没有使用 `C`，因为宇宙刻意聚焦具备技术训练价值的实体，而非泛岗位池。

### 5.2 初始匹配层

- `P0`（121）：值得重点下钻业务线、岗位和技能树。
- `P1`（138）：强相关备选或地区/方向补充。
- `P2`（13）：细分入口、资格不确定或需谨慎评估具体岗位。
- `P3`（1）：主要作为产业情报节点，而非直接技术目标。

这不是最终个人排序。缺少个人学位、毕业时间、国籍/工作资格、地点、语言、项目、论文、流片、实习和作品集时，不能诚实地产生“录取概率”。

### 5.3 置信度

- `high`：230 个；有稳定官方实体、机构或招聘页面。
- `medium`：42 个；常见原因是招聘入口不稳定、采用上级集团/协会/政府页，或机构名称与路径仍需二次确认。
- `low`：1 个；保留为明确的滚动核验对象，不能用于声称当前机会。

## 7. v2 的局限与滚动待办

1. 这是实体级宇宙，不是当前开放职位数据库。
2. 一些集团内部芯片团队没有独立法人或稳定官网，已优先使用明确实体；腾讯、字节、vivo 等只按系统/AI 基础设施纳入，不能据此声称存在当前芯片岗。
3. 中国电科研究所部分采用集团或研究所主页证据；下一轮必须为每个目标岗位补独立人事公告、专业目录和资格要求。
4. 高校节点是学院入口；下一轮必须下钻到导师、实验室、招生批次、科研助理合同与联合培养协议。
5. 平台和联盟容易被误当作雇主；岗位层必须拆分运营主体、项目主体和实际用工主体。
6. 设备材料还有大量零部件、电子特气、湿电子化学品和厂务企业；v2 只保留跨过独立身份、技术相关性与一手证据门槛的高相关节点。
7. 台湾、港澳和外资在华研发/制造节点未系统展开，应另建区域/主体清晰的数据集，避免法律与招聘市场混用。
8. `careerUrl` 需要定期健康检查；主页可用不代表招聘页可用。
9. 所有 fit 与 difficulty 都必须在读入个人背景后重算。
10. 对每个具体申请，仍需保存当期 JD 证据，不能只引用本文件。

## 8. 数据质量门槛

v2 交付前的机器自检要求：

- JSON 顶层为数组。
- 实体数不少于 180。
- `id` 全部唯一。
- 每项严格包含约定的 22 个字段。
- `aliases`、`categories`、`locations`、`focusAreas`、`roleFamilies`、`requirements`、`gaps`、`opportunityTypes`、`evidence` 均为数组。
- 每项至少一个证据，证据包含 `title`、`url`、`type`、`observedAt`。
- `fitTier ∈ {P0,P1,P2,P3}`。
- `difficulty ∈ {S,A,B,C}`。
- `visaSignal ∈ {friendly,mixed,restricted,unverified}`。
- `confidence ∈ {high,medium,low}`。
- `lastVerified` 和 `evidence.observedAt` 使用 `YYYY-MM-DD`。
- 不出现重复名称、空 ID、非 HTTP(S) 证据 URL。

这份 v2 的正确用途，是帮助建立中国相关目标的全景地图并决定下一轮调查顺序；它不是把 273 个实体一次性全部投递。
